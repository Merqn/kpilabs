# SPEC - Завдання 3: Взаємодія UC-02

## Обраний use case

**UC-02 «Організувати особистий плейлист».** Актор - слухач (спеціалізація
користувача). Мета - створити власний плейлист або додати трек до наявного
плейлиста. Основні учасники взаємодії:

- `Слухач` - ініціює запити користувача.
- `PlaylistAPI` - приймає HTTP-запит і запускає потрібну операцію.
- `AuthService` - перевіряє автентифікацію та право власності.
- `CatalogService` - перевіряє наявність треку в каталозі.
- `PlaylistService` - координує перевірки та додавання запису.
- `PlaylistRepository` - читає й змінює сутності `Playlist`/`PlaylistTrack`.
- `Database` - зберігає дані моделі Завдання 1 у транзакції.

Зовнішні поштові та платіжні служби не беруть участі в сценаріях.

## S1: Створити плейлист і додати наявний трек

Кроки:

1. Слухач автентифікується та надсилає назву плейлиста й ID треку.
2. `PlaylistAPI` викликає `AuthService.validateUser()`.
3. `PlaylistService` перевіряє назву та створює сутність `Playlist`.
4. `CatalogService` перевіряє `Track.track_id`.
5. У транзакції створюється запис `PlaylistTrack` на позиції 1.
6. Користувачу повертається результат із ID плейлиста й позицією треку.

Діаграма: [Mermaid](artifact/S1-create-and-add.mmd) |
[рендер SVG](artifact/S1-create-and-add.svg).

## S2: Додати трек до створеного власного плейлиста

Кроки:

1. Слухач передає ID плейлиста та ID треку.
2. Перевіряються автентифікація, власність і наявність треку.
3. Репозиторій читає поточні записи `PlaylistTrack`.
4. Система знаходить максимальну позицію.
5. У транзакції створюється наступний запис на `max(position) + 1`.

Діаграма: [Mermaid](artifact/S2-add-to-existing.mmd) |
[рендер SVG](artifact/S2-add-to-existing.svg).

## S3: Відхилити повторне додавання треку

Кроки:

1. Слухач повторно надсилає трек для плейлиста.
2. Перевіряються автентифікація та власність.
3. Репозиторій перевіряє пару (`playlist_id`, `track_id`) у
   `PlaylistTrack`.
4. При наявності запису операція завершується повідомленням
   «Трек уже є у плейлісті» без зміни даних.

Діаграма: [Mermaid](artifact/S3-reject-duplicate.mmd) |
[рендер SVG](artifact/S3-reject-duplicate.svg).

## S4: Заборонити додавання до чужого плейлиста

Кроки:

1. Слухач передає ID чужого плейлиста та треку.
2. `AuthService` перевіряє `Playlist.user_id`.
3. При відмінності власника користувачеві повертається HTTP 403.
4. Перевірка каталогу й запис у `PlaylistTrack` не виконуються.

Діаграма: [Mermaid](artifact/S4-reject-foreign.mmd) |
[рендер SVG](artifact/S4-reject-foreign.svg).

## S5: Відхилити додавання відсутнього треку

Кроки:

1. Слухач передає ID треку, якого немає в каталозі.
2. Перевіряються автентифікація й право власності.
3. `CatalogService` не знаходить `Track.track_id`.
4. Система повертає «Трек не знайдено»; запис у `PlaylistTrack`
   не створюється.

Діаграма: [Mermaid](artifact/S5-reject-missing-track.mmd) |
[рендер SVG](artifact/S5-reject-missing-track.svg).
